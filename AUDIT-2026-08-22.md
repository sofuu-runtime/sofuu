# Sofuu Codebase Audit — 2026-08-22

Full-project audit covering four axes: **wiring/dead code**, **FFI/`unsafe` correctness**,
**security**, and **shipped-JS driver logic**, plus live verification of the test suites.

- Scope: `crates/` (sofuu-core, sofuu-ffi, sofuu-capi, fuzz), `src/js/`, `src/simd/`,
  `include/`, `tests/`, `examples/`, `scripts/`, `.github/workflows/`, `Makefile`,
  `install.sh`, README/plan docs. Excluded: `black-hole-disk-for-sofuu-runtime/`,
  `new-model-arch./`.
- Method: read-only audit (no fixes applied at audit time), cross-checked against
  `deps/quickjs`, `deps/libuv`, `deps/http-parser` headers; live probing of the built
  binary; test suites re-run from scratch.
- Test verification (2026-08-22): `cargo test` → **185 passed / 0 failed**;
  `make test` → **19/19 passed**; binary 2.1 MB ≤ 5 MB cap.

## Executive summary

The runtime is genuinely in good shape on its verified claims: all Rust and JS tests
pass, the README's API surface is honest (every documented API is registered and live),
all 30 `__chat_*` and 8 `__rlm_*` bridges are wired with matching arity, and the
security fundamentals (npm tar safety, RLM sandbox hardening, TLS verification, CRLF
blocking) hold up under scrutiny.

The audit found:

1. **One repo-state emergency**: the entire Rust implementation (~30k lines) is
   untracked in git; a fresh clone builds the obsolete C alpha.
2. **Six memory-safety bugs** in failure/edge paths (double-free, two UAFs, a
   heap over-read class, a multi-runtime teardown hazard).
3. **A documented feature that cannot work**: brain-server bearer auth reads
   `req.headers`, but the native HTTP server never parses headers — every request
   401s, always; the auto-generated token is a formatted timestamp (zero entropy).
4. **A systematic gap** between the agent budget/cancel contract in PLAN-AGENTS.md
   and what `src/js/agent.js` actually enforces.
5. A tail of leaks, dead code, stubs that report success, and JS-driver logic bugs.

## P0 — act on these first

### P0-1. The entire Rust implementation is not committed to git

`git ls-files crates/` is empty; `Cargo.toml`, `include/`, `tests/`, `docs/`, and the
shipped JS drivers are untracked; the `src/**.c` deletions are unstaged. 16 commits
exist but the newest substantive ones predate the migration. A fresh clone checks out
the old C tree with the old Makefile; CI on push would test the old code. One `rm -rf`
away from losing ~30k lines of work.

### P0-2. Double-free on every failed `sofuu.spawn`

`crates/sofuu-core/src/rt/process_spawn.rs:409` assigns `req.process = process`
**before** `uv_spawn`. On spawn failure (`:465-479`), the error path frees `process`
directly, sets `closing = 3`, and lets the pipe-close fence call `spawn_free(req)`
(`:58-60`) — which unconditionally frees `(*req).process` **again**. The failure-path
comment claims "the process handle is freed here", but `spawn_free` was never taught
that. Triggers on `sofuu.spawn("nonexistent", [])`. Verified by reading both paths.
(The `js_sofuu_exec` failure path at `:761-766` does it correctly.)

### P0-3. Use-after-free in `mcp.connect` failure cleanup

`crates/sofuu-core/src/rt/mcp.rs:663-669`: on connect failure the code calls
`uv_close(pipe, None)` for the initialized pipes and then immediately `libc::free`s
the same storages. `uv_close` is asynchronous — the handles sit in
`loop->closing_handles` and libuv reads/writes them (including the `close_cb` field)
on the next loop iteration, after the memory is freed.

### P0-4. Heap over-read via NUL bytes in network data

Pattern `CString::new(data).unwrap_or_default()` + the **original** `data.len()`
passed to QuickJS (which trusts the length against a buffer that must be
NUL-terminated): when `data` contains a NUL, the CString collapses to a 1-byte empty
buffer while QuickJS reads `len` bytes past it. Sites:
- `crates/sofuu-core/src/rt/http_client.rs:134-138` (`response_text_impl` —
  `fetch().text()` on a NUL-containing body),
- `rt/http_client.rs:399-400` (`headers_get`),
- `rt/ai.rs:1149-1150, 1226-1227, 1802-1803, 1903-1904, 1917-1918, 2164-2165`
  (`JS_ParseJSON` over SSE/stream data — a hostile or buggy provider sending NUL
  bytes inside a `data:` line triggers it).

`response_json_impl` (`http_client.rs:200-206`) shows the correct discipline.

### P0-5. Brain server auth is structurally dead code (+ zero-entropy token)

- The native HTTP server configures the vendored parser with `on_header_field: None,
  on_header_value: None, on_headers_complete: None`
  (`crates/sofuu-core/src/rt/http_server.rs:440-454`); the handler `req` object gets
  only `{method, url, body}` (`:365-399`).
- The brain server script checks `req.headers && req.headers.authorization`
  (`crates/sofuu-core/src/main.rs:554`) → `req.headers` is always `undefined` →
  **every request returns 401**. The feature (`sofuu serve --brain`) cannot work.
- Compounding: the auto-generated token is `format!("sofuu-{:016x}", epoch_micros)`
  (`main.rs:498-503`) — no CSPRNG anywhere; a ~10⁶/second brute-force space. Printed
  to stderr, persisted 0600 (the persistence is good).
- The remote-bind guard only checks `token.starts_with("sofuu-")` (`main.rs:517`) —
  a user-supplied `--token sofuu-anything` bypasses the "explicit token" requirement.
- The JS comparison `auth !== 'Bearer ' + token` is not timing-safe.
- Related in the same function: the script iterates `req.body` (a pre-buffered
  `String`, `http_server.rs:392-397`) as a chunk stream — char-at-a-time O(n²)
  concatenation (`main.rs:570-571`).

### P0-6. Stale opaque pointer: Subprocess JS object outlives the native request

The close-callback fence frees `SpawnReq` shortly after process exit but never nulls
the JS object's opaque, so post-exit `.write()`/`.kill()` dereference freed memory
(`rt/process_spawn.rs:489-495` vs fence `:68-80`, `:172-178`). Purely JS-triggerable.
Adjacent leak in the same lines: `js_subprocess_finalizer` overwrites
`on_stdout/on_stderr/on_exit` with undefined without freeing the old values
(`:190-194`) — the handler refs leak whenever the object is GC'd before process exit.

### P0-7. Multi-engine teardown leaves engine A's callbacks armed on the shared loop

With >1 engine alive, `sofuu_loop_close` decrements `G_LOOP_REFS` and returns early
(`rt/loop.rs:149-151`); `engine_destroy` then frees the context, but that engine's
still-armed timers fire later on the surviving loop: `on_timer` (`rt/timer.rs:89-122`)
calls into the freed `JSContext*`. Same for in-flight curl fetches and MCP clients;
`mod_process_cleanup` tears down process-global stdin/TTY state for all engines.
Sequential single-engine create/destroy is fine; the capi-documented
"one runtime per thread, multi-runtime per process" mode (`sofuu-capi/src/lib.rs:18-20`)
is not actually safe. Also `sofuu_loop_init` uses Relaxed load+store without CAS
(double-init race), and `unsafe impl Send for SofuuRuntime` invites cross-thread
migration QuickJS cannot survive. **Architectural fix (per-engine handle tracking or
loop-per-runtime) — deferred to its own focused pass; capi docs should carry an
explicit warning until then.**

## P1 — contract violations & security

### Agent budget/cancel contract (PLAN-AGENTS.md A5) vs `src/js/agent.js`

1. **Children do not inherit the parent's remaining budget** (`:641-647`, `:810-836`):
   only token counters are tree-shared (`_treeUsage`); every cap check uses the
   current node's own def. A child whose `maxTokens` is below already-spent tree
   tokens dies instantly; a child with a larger cap legally exceeds the root budget;
   `maxSteps` is per-run (`:620`) and `maxWallMs` restarts per run (`:607`) — a root's
   budget is decorative after delegation.
2. **`cancel()` does not propagate to delegated sub-runs** (`:782-808`, `:810-836`,
   `:1076-1085`): no signal/parent-child state link; the `delegate` tool is the one
   path not wrapped in `withTimeout` (`:787-794`). Esc during a delegated chat turn
   blocks until the child exhausts its full (default 300 s) budget.
3. **Chat's `maxDepth:1` guarantee is false** (`chat.rs:3190-3222`, `agent.js:723`):
   the depth gate uses each node's own def; registry agents default to `maxDepth:2`,
   so chat → agent → grandchild runs at depth 2.
4. **Global `__rlm_aborted` flag** (`rlm.js:145-159`): concurrent RLM episodes
   cross-contaminate — cancelling one kills the other; a new episode swallows a
   pending abort of the previous one.

### Security (High/Medium)

- **M1. `fetch()` follows redirects with custom headers re-sent to the target**
  (`rt/http_client.rs:1136` `CURLOPT_FOLLOWLOCATION=1` with JS headers on the slist):
  an attacker-influenced 30x exfiltrates `Authorization`/`Cookie` from user scripts.
  AI provider calls do not follow redirects — provider keys are not exposed.
- **M2. npm tarball**: unbounded gzip inflate (`npm.rs:277-285`), no aggregate size
  cap in `extract_tar` (`:287-350`), and a reachable slice panic when a header
  declares a size past EOF (`:341`). The SHA-1 comes from the same registry response,
  so it is transport integrity, not registry-compromise integrity. Registry is
  hardcoded HTTPS; meta capped at 64 MB.
- **M3. `fetch()` response-header accumulation is unbounded**
  (`rt/http_client.rs:833-857`) — multi-GB heap growth from a malicious server within
  the 120 s timeout (body is capped at 256 MB; headers are not).
- **M4. `@file` mention root-escape check is string-prefix only**
  (`chat.rs:2618-2627`): a symlink inside the project pointing at `~/.ssh/id_rsa`
  passes and is read into the prompt. `..`-rejection itself works; a `canonicalize`
  placeholder exists but is not called.
- **M5. Session `.qtsq` "encryption" key is derivable by any local process**
  (`session.rs:216-224`): `"sofuu-session-" + fnv1a64(project_path)` — not a KDF, no
  secret; documented in-code as local obfuscation. Chat transcripts (300/2000 chars
  per turn) are recoverable by anyone who can read the files.
- **M6. HTTP server**: JS-controlled `Content-Type` spliced into the response
  unvalidated → response splitting (`rt/http_server.rs:171-207`, `:224-243` truncates
  to 255 bytes but never rejects CR/LF); default bind `0.0.0.0` (`:525, 550, 628`).
  Request-side caps are good (URL 8 KB, body 16 MB, malformed requests closed).
- **M7. MCP child can wedge all pending calls**: fixed 64 KB line buffer
  (`rt/mcp.rs:36, 246-249`); once full without a newline, `copy = 0` forever and all
  pending promises hang (rejected only on process exit). `MAX_PENDING=64` cap exists.

## P2 — broken-but-quiet, leaks, dead code

- **RLM turns are invisible to token budgets and `/cost`**: `rlm.js:60-92` discards
  stream usage → `budget_tokens` can never fire during an RLM episode; chat reports
  0/0 for RLM turns (`chat.rs:3327-3343`). Parent `usage.tokens` also excludes
  sub-run tokens (`agent.js:829-835`) — every delegating turn under-counts in `/cost`.
- **Chat context-window lookup keys on `cfg.provider`** (`chat.rs:2939-2944`) — since
  the provider wizard that field is the user-chosen name ("groq", …), so every
  custom-named provider gets the 32k default and premature compaction, while the RLM
  gate uses the model-based `MODEL_CTX` table for the same turn.
- **Two independent brain handles on the same `.qtsq` file**
  (`chat.rs:2469-2482` driver handle vs `agent.js:312-339` BRAINS cache): whole-file
  flushes clobber each other; `brainDecayTick` renumbers record ids the driver handle
  never sees. `/remember "pin"` can be silently erased by the next agent turn.
- **Leaks**: every `mcp.connect` leaks its JS object (`self_val` never freed,
  `mcp.rs:66, 85-91, 603`); every `mcp.serve()` leaks the whole server permanently —
  the `self_val` self-reference cycle is invisible to QuickJS GC so the finalizer
  never runs (`mcp.rs:1181-1193`, `:731-741`), which also masks a latent UAF
  (stdin pipe never `uv_read_stop`/`uv_close`d); `write_str_dup` ignores the
  `uv_write` rc → per-call leak on EPIPE (`mcp.rs:128-139`); ai-stream CURLM-failure
  path misses `tool_calls_fn` (`ai.rs:2902-2914`); `pending_resolve` leaked in the
  response finalizer (`http_client.rs:92, 100-128`).
- **Dead code**: 23 of 28 C-ABI shims in `ffi_exports.rs` have had zero callers since
  the C core was deleted (`sofuu_jsonrpc_*` ×6, `sofuu_npm_resolve_rs`, all 16
  `sofuu_cma_*`); `cfg.brainPath` is read by the chat driver but never serialized
  (permanently `undefined`, `chat.rs:2471`); ghost-completion's debounce timer is
  declared/read but never assigned — full embed+recall runs on every keystroke
  (`chat.rs:2880-2913`).
- **Stubs that report success**: `POST /share` in `sofuu serve --brain` returns
  `{"ok": true, "message": "share endpoint not yet implemented"}` (`main.rs:620-623`)
  while the startup banner advertises it (`:534`); `sofuu.ai.embed(…, {provider:
  "local"})` hard-throws (`ai.rs:2948-2954`) while the module comment claims local
  chat isn't built at all (`:48` — it is, via Ollama).
- **Build landmine**: both `build.rs` files default `SOFUU_QTSQ_DIR` to
  `/Users/priyanshuboruah/projects/black-hole-disk` — every other machine silently
  builds without the entire memory subsystem (`rt/memory.rs:1992-2027` no-ops) and
  `examples/agent_test.js:308` fails.
- **JS-driver logic (selected)**: `trimHistory` measures only stored history, never
  the current turn (attachments up to 8192 tokens can push the real request past the
  window, `chat.rs:2973-3003`); `/why` shows stale recall after a zero-recall turn
  (`chat.rs:3273-3276`, `agent.js:688-692`); every `@word` in a prompt becomes a
  bogus attachment ("email me at bob@example.com" attaches `example.com`,
  `chat.rs:2589-2598`); `web.open` returns error-page bodies as success and mangles
  `&#128512;`-class entities (`web.js:251-282`); DDG snippet/result misalignment
  (`web.js:95-122`); name-less streamed tool calls silently dropped → `'(no response)'`
  (`agent.js:519-527`); `capToolResult` head is unconditional so small
  `maxToolResultChars` caps are violated (`agent.js:587-597`); `runs24h` counts
  delegated children and mapContext fan-out (`agent.js:121-126`); `'(cancelled)'` /
  `'(no response)'` answers are pushed into chat history (`chat.rs:3349-3352`).

## P3 — low severity / cosmetic (selected)

- RLM sentinel "spoof-proof" claim is inaccurate: any thrown `\0RLM_*:` string is
  trusted (`ffi/qjs_rt.rs:316-330`, `rlm/sandbox.rs:274-294`), though the capabilities
  gained are equivalent to the real API and all budgets/anti-loop guards still apply.
  `__LLM_CACHE`/`__TOOL_CACHE` are deliberately unfrozen — snippet code can pre-seed
  answers (integrity issue, not an escape).
- Brain-file vault password is hardcoded (`"sofuu-kv-local-v1"`,
  `rt/memory.rs:58-62`) — at-rest obfuscation only (documented in-code).
- `routing_log.jsonl` stores user questions in plaintext with default perms
  (`rlm/router.rs:125-139`).
- MCP children inherit the full parent environment incl. API keys
  (`rt/mcp.rs:643` `env: null`) — Node-equivalent, but notable for shared mcp.json.
- `install.sh` is solid (HTTPS-only, sha256 enforced pre-extraction, refuses without
  a checksum tool) but TOFU — checksum comes from the same release as the binary.
- `/import` displays card fields without ANSI stripping (`chat.rs:2738-2739`).
- `UV_DISCONNECT = 0` in `ffi/uv.rs:51` is wrong (should be 4) — currently unused,
  latent trap. uv handle-type constants are correct only for the vendored libuv
  (fragile by design).
- curl message-purge assumption in `stream_abort_one` (`ai.rs:1716-1721`) relies on
  libcurl ≥ 8 behavior — version-dependent UAF risk on older system curls.
- User JS is executed inside the curl write callback (`ai.rs:1727-1989`) — anticipated
  and guarded, but structurally delicate. Promise rejection from a GC finalizer
  (`http_client.rs:100-128`) is outside QuickJS's documented supported use.
- Unchecked `libc::malloc` (null-deref on OOM) at `timer.rs:154/291`,
  `process_spawn.rs:405-408`, `http_server.rs:502/518`, `mcp.rs:608-611/1131-1132`,
  `ai.rs:1535`. `bridge.rs:40-41` comment states JS_SetPropertyStr refcount semantics
  backwards (code is right; invites a future double-free). Native-registered
  namespaces are non-enumerable (`Object.keys(sofuu.ai)` → `[]`) while `sofuu.fs`
  is enumerable — inconsistent reflection surface. Stale comments: REPL "Phase 0
  delegate to C REPL" (`main.rs:204-218`), rlm.js `:40-43`, `js_api.rs:4` ("seven"
  natives, eight registered).
- Root-dir build junk: `mod_ai.o`, `sofuu-sym` (1.9 MB, not gitignored),
  `fix_*.patch`, `extreme_memory_test.js`.
- Prompt injection: web/MCP tool outputs flow into the agent transcript as plain
  strings with no delimiters or sanitization (the one mitigated surface is
  peer-session notices, sanitized + labeled UNTRUSTED).

## Checked and found safe (evidence-backed)

- **npm**: spec validation rejects `../x`, `a@../../b`, absolute paths, control
  chars (`npm.rs:20-35`); tar members reject absolute/`..`/symlinks, hardlinks and
  devices ignored, mode bits never applied (`npm.rs:321-345`); extraction target
  symlink refused, temp via `mkstemp` 0600 (`rt/npm.rs:284-291, 212-219`); SHA-1
  enforced and fails closed when missing (`rt/npm.rs:257-270, 194-205`); registry
  hardcoded HTTPS, meta capped 64 MB, 404s fail the tarball fetch.
- **RLM sandbox**: memory 32 MB / stack 1 MB limits set (`qjs_rt.rs:214-215`,
  `sandbox.rs:92-94`); interrupt-handler wall-clock deadlines; trace capped 512;
  cache-injection double-JSON escaping with hostile-bytes round-trip test; whitelist
  `writable:false, configurable:false`, `Math` frozen, `Date` stubbed; no module
  loader → no `import()`; natives take primitive args only; memory-bomb and
  `while(1)` tests pass.
- **TLS**: `CURLOPT_SSL_VERIFYPEER=1` explicitly on all AI calls (`ai.rs:2665, 2888,
  3021`); VERIFYHOST never disabled.
- **CRLF injection blocked** on both paths: API keys with CR/LF skipped (`ai.rs:668-
  673`); fetch header names/values with CR/LF skipped (`http_client.rs:1177-1189`).
- **HTTP server request parsing**: vendored parser handles content-length/chunked;
  URL 8 KB, body 16 MB caps; malformed requests closed (`http_server.rs:27-28,
  347-363, 474-481`).
- **Session mesh**: strict session-id validation blocks registry traversal
  (`session.rs:265-287` + test); registry RMW under `flock` with atomic tmp+rename;
  peer text ANSI-sanitized and labeled UNTRUSTED in the system prompt.
- **MCP spawn is shell-free**: custom tokenizer + direct `uv_spawn` argv
  (`mcp.rs:498-551, 632-650`); inbound JSON-RPC parsed with serde, bounded by the
  64 KB line buffer.
- **Web scrape regexes**: no nested/unbounded quantifier overlap — no catastrophic
  backtracking; `web_open` enforces `^https?://`.
- **Config**: written 0600 via tmp+rename (`chat.rs:344-349`); provider list prints
  "key set", never the key; AI errors use `curl_easy_strerror` only.
- **Wiring**: all 30 `__chat_*`, 8 `__rlm_*` bridges consumed with matching arity;
  every README-documented API registered and live; capi exports match
  `docs/EMBEDDING.md`; no dead config keys; `include_str!` targets all exist on disk.
- **JS driver correctness that held up**: full-path cycle guard (A→B→C→A caught);
  exact `maxSteps` semantics (no off-by-one); `runMany` isolation (per-item
  try/catch, workers cannot reject); MCP connect uses `allSettled`;
  settle-once/no-unhandled-rejection discipline in `withTimeout`/`withCancelGuard`;
  `memory:'off'` provably writes nothing; recall gating math and compaction
  semantics match PLAN-MEMORY-TOKENS.md exactly; trace ring and entity prefixing as
  documented; episode round/llm-call accounting consistent.
- **Struct mirrors verified against headers**: `JSCFunctionListEntry` (32 B),
  `JSPropertyEnum`, JSValue (16 B non-NaN-boxed), `JS_TAG_*`/`JS_EVAL_*`, http-parser
  bitfields + accessors, `uv_process_options_t`/`uv_stdio_container_t`/`UvBuf`/
  `uv_stat_t`, `CurlMsg` overlay, CURLOPT/CURLMOPT constants. `Rooted` drop-before-
  FreeContext respected at all checked call sites; promise handle malloc/free pairing
  exact; fs/timer/http_server callback fences sound; ESM loader NUL-sentinel and
  module value free order correct; qtsq alloc/free ordering pinned by tests; signal
  handlers flag-only (async-signal-safe); no raw SIGCHLD handling (libuv owns reaping).

## Recommended fix order

1. **Commit the tree** (P0-1).
2. JS-triggerable memory bugs: P0-2, P0-3, P0-4, P0-6 — small, isolated failure-path fixes.
3. Brain server: wire header parsing, CSPRNG token, timing-safe compare (P0-5).
4. Agent budget/cancel contract: implement tree-inherited budgets + cancel
   propagation, or fix the docs to match reality (P1-agents).
5. Redirect header stripping, npm inflate/size caps, fetch header-accumulation cap
   (M1–M3).
6. P2 batch: RLM usage accounting, ctx-window keying on `cfg.profile`, dual brain
   handles, MCP leaks, dead `ffi_exports` shims, `/share` honesty.
7. P0-7 (multi-runtime teardown) as its own architectural pass.
