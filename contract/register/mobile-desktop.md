## Notes for the coordinator

- **Shared-file change needed (outside this worker's scope): `CHANGELOG.md`.** The AAR's `SofuuBridge.similarity(a, b)` changed its return type from `Float` to `Float?` (`bindings/android/.../SofuuBridge.kt:362`). That is source-breaking for Kotlin callers: `val s: Float = bridge.similarity(a, b)` no longer compiles; `val s = bridge.similarity(a, b)` (nullable) does. No in-repo caller uses it (the copy under `examples/headless/KotlinSample/` is a separate file and was left untouched), but the AAR is a published artifact — the break should be noted in the changelog and, if the AAR is versioned separately, in its release notes. The alternative (returning `0f` again) is the fabrication this work removes.
- **Desktop app build + a real turn is the remaining D10 work.** Everything the shell displays is now sourced from the runtime, and the runtime side is proven, but "the app was launched and a turn ran" needs someone who can build the Tauri crate. Suggested check once it can be built: `npm run tauri dev` with a local GGUF provider, then confirm (1) the session strip lists the engine's own sessions, (2) `/remember` writes to the workspace brain and `/why` reports the honest refusal, (3) Settings → Usage shows the engine's totals, (4) killing the engine produces an error banner rather than an empty strip.
- **`cancel_turn` / `resolve_approval` cannot report delivery.** `sofuu_core::rt::host_poke::host_poke_send` returns `()` (`crates/sofuu-core/src/rt/host_poke.rs:56`), so the desktop cannot distinguish "the engine took the approval" from "the message is still queued". The UI resolves the approval row locally; the engine's own event stream is what actually shows the outcome. Making delivery observable needs a status return from `host_poke_send` — a change in `crates/sofuu-core`, outside this worker's scope, and it is fail-closed today (an undelivered approval blocks the tool rather than allowing it).
- **Do not read the D09 row as device coverage.** `contract/CAPABILITY-REGISTER.md` already splits D09 into the host-JVM row (`real`, host JVM only) and the device row (`unverified`); this report keeps the same split and adds the AAR-helper (`pure`) and packaging (`unverified`) rows.
- **No weights were downloaded.** The only model used is the pre-existing `~/Downloads/SmolLM2-360M-Instruct-Q8_0.gguf`; nothing was fetched, moved or deleted.
