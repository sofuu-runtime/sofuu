## Executive summary

The fundamentals that past audits fixed are still fixed (spawn fence, argv NUL, mcp
pipe cleanup, CString length discipline, http-server auth, budget-stop rendering — all
re-verified this pass). The engine and the Rust/JS test spine are in genuinely good
shape. What this audit found:

1. **One wrong constant in the QuickJS flag mirror** (`JS_PROP_CONFIGURABLE = 0x10`,
   correct value `0x01`) — every Rust-registered native function list (21 shipped
   entries) silently loses configurability, and the constant is a latent heap-corruption
   gun if ever used through a direct `JS_DefineProperty` path.
2. **The 2026-08-24 maxSteps fix landed in only ONE of the two chat drivers** — the
   shipped `src/js/chat.js` (which every embedded/headless host runs) still caps tool
   loops at **8 rounds** while the TUI driver allows 200.
3. **Token/cost accounting is largely theater on OpenAI-compatible streams** —
   `stream_options: {"include_usage": true}` is never sent, so `st.usage` stays 0 for
   spec-compliant OpenAI providers: `budget_tokens` can never fire, `budget_usd` never
   trips, and the ctx meter silently degrades to its estimator. Continuation and
   empty-stream-retry paths drop usage from the streams they abandon.
4. **The write jail is lexical only** — a symlink inside the project defeats
   `mustBeInRoot` (fs has no canonicalize/realpath anywhere), so `write_file`/`edit_file`
   can write outside the project through a pre-existing link; and there is **no SSRF
   guard anywhere** in the fetch/web layer (localhost, RFC1918, cloud metadata all
   reachable).
5. **Silent-drop classes in the session layer**: PeerWatch marks >8-event bursts as seen
   without delivering them; every session persist failure is `let _ =`-discarded;
   negative provider usage can walk the USD spend cap backwards.
6. **ML runtime/trainer asymmetries**: the supervisor's step/budget features are
   trained on one-call-per-step but fed tool-call-count-at-runtime (spurious
   over-budget nudges); compaction's plan() budget sum still wraps (the hardening fix
   landed in features.rs only); alloc's error parser misclassifies dual-keyword
   context errors and misses "context window/size" wordings.
7. **Build/repro gaps**: uncommitted vendored-QuickJS MSVC changes + untracked
   `msvc-compat/` (Windows builds-from-clone are broken), the ABI checker exits 0 on
   *new* symbols, root `cargo test` compiles the whole Tauri desktop stack, and two
   different Linux binaries ship with different TLS capability under one product name.
8. **Public-API text corruption**: `sofuu.SSEParser` (the exported JS class) decodes
   each feed chunk lossily — multi-byte UTF-8 split across network reads becomes two
   U+FFFDs (the internal ai.rs parser is byte-safe; the exported one is not).

No active memory-safety P0 was found in the CLI path itself; the two P0-class hazards
that remain (multi-engine teardown, multi-runtime config cross-talk) are embedded-host
issues, documented open since 2026-08-22 and still open.

# P0 — latent crash / heap-corruption / cross-talk hazards

## F-1. `JS_PROP_CONFIGURABLE` mirrored as `0x10` — wrong value (correct: `0x01`) — **FIXED 2026-09-02**

> **Fixed**: `qjs.rs` constant changed `0x10 → 0x01` (with a header-cite
> comment). Verified: cargo build clean; 266/0 + 28/0 + 3/0 Rust tests;
> JS suite 20/20; agent_test.js ALL PASSED; live probe on the rebuilt
> `./sofuu` confirms `configurable=true/writable=true` on native
> registrations across ml/supervisor/freshness/compaction/alloc/mcp/
> SSEParser/CMA/ai.

`crates/sofuu-ffi/src/qjs.rs:659` — `pub const JS_PROP_CONFIGURABLE: u8 = 0x10;`
The vendored header (`deps/quickjs/quickjs.h:263`) defines it as `(1 << 0)` = **0x01**;
bit 0x10 is `JS_PROP_GETSET` territory (`JS_PROP_TMASK = 3 << 4`). 21 shipped
`JSCFunctionListEntry`s across ai.rs (10), ml/mod.rs (6), memory.rs (2),
process_spawn.rs (2), http_sse.rs (1) build `prop_flags = WRITABLE|CONFIGURABLE =
0x12`.

Verified mechanism (lead-auditor, against quickjs.c source): the function-list path
routes through `JS_InstantiateFunctionListItem` → `JS_DefineAutoInitProperty`
(quickjs.c:9327), which stores `(flags & JS_PROP_C_W_E) | JS_PROP_AUTOINIT` — the bogus
0x10 bit is **masked out** for these autoinit properties. So today's observable effect
is a spec-contract break: all 21 native properties are **non-configurable** (the
"configurable" intent silently lost), not corruption. The corruption case is any future
use of the constant through `JS_DefineProperty`/`add_property` directly (as
quickjs.c:8950 does internally): a property stored with a 0x10 flag bit is freed through
the GETSET union in `free_property` (quickjs.c:5196) → refcount-free of an
attacker-influential pointer.

**Fix: one character** — `0x10` → `0x01` (and re-verify the freeze: natives become
configurable, which is what the code always claimed).

## F-2. Multi-engine teardown: engine A's armed handles on the shared loop + wrong-context frees (P0-7) — **FIXED 2026-09-10**

> **Fixed**: per-context armed-handle registry in `rt/loop.rs`
> (`track_handle`/`untrack_handle`/`sofuu_loop_shutdown_engine(ctx)`). Every armed uv
> handle now attributes to its owning JSContext — timers (create + sleep), host-poke,
> AI poll handles, HTTP server (client/hdr-timer/listener), spawn/exec, MCP client +
> server pipes, stdin/TTY/readline machinery — and every close callback untracks.
> Multi-engine `engine_destroy` now aborts the dying engine's in-flight AI requests
> first (stream: curl remove + destroy, no user JS runs; complete/embed: promise
> reject "engine shutting down"), then drains ONLY its registry entries (`uv_close`
> with each handle's own close callback + a UV_RUN_NOWAIT drain) while its ctx is
> still live, and only then frees the context — engine B's handles survive untouched.
> `mod_process_cleanup` gained first-writer-wins owner guards
> (STDIN_OWNER/TTY_CTX/STDIN_CTX) so a dying engine can no longer free a surviving
> engine's stdin-callback JSValues through the wrong context, and stale
> ESC/notice-timer pointers are reset (a walk-closed handle can't be re-armed by the
> next engine). `host_poke` gained `sofuu_host_poke_shutdown_for(ctx)` (its
> first-engine-owns limitation is kept and documented). Regression test
> `rt::event_loop::tests::shutdown_engine_closes_only_that_ctx_armed_handles`: two
> engines, A destroyed mid-flight with a 50ms timer armed, B's 200ms timer must still
> fire; the white-box registry asserts make the old behavior fail the test
> deterministically (and the UAF itself is caught by any sanitizer build).
> Gates: sofuu-core 378/0, capi 22/0, ffi 11/0, JS suite 41/0/1.
> **Honest residuals** (each is the identical gap that exists in today's
> single-engine teardown, so no regression): in-flight `http_client` fetches are not
> registry-tracked (no abort path); `uv_fs_t` requests are invisible to `uv_walk`;
> spawn/exec/MCP-client boxes stay fence-freed (parity leak on teardown).

`rt/loop.rs:59-79,143-160` now refcounts the global loop; `engine_destroy`
(rt/engine.rs:754-767) runs host_poke shutdown → loop close (no-op if refs>1) → process
cleanup → GC → free ctx → free runtime. With engines A and B alive, destroying A does
NOT close A's libuv handles (loop close bails at `loop.rs:150`), then frees A's context —
A's still-armed timers/pipes/polls carry `data` pointers into freed Rust boxes, and the
next `uv_run` on B fires them into a freed context (UAF). Additionally
`mod_process_cleanup` uses thread-local state keyed by ctx; two engines on one thread
share the cells, so A's destroy can free B's stdin-callback JSValues **through the wrong
context** (wrong-context free is itself UB in QuickJS).

`host_poke.rs:128-129` documents the punt: "exactly one runtime per process in every
embedded host". CLI/desktop are single-engine and unaffected; capi's
`multi_instance_two_runtimes_independent` test only checks JS-variable isolation, not
config or pending I/O. **Open since 2026-08-22, unchanged.**

## F-3. (Downgraded from agent P0) `sofuu_rt_new` writes process-global config from per-runtime args — **FIXED 2026-09-10**

> **Fixed**: embed config moved from process-globals to per-runtime thread-local
> settings — `embed_config.rs` holds `RtSettings` in a `thread_local! CURRENT` cell;
> `configure`/`set_api_key`/`set_brain_path` write the calling runtime's settings and
> `current_settings()` reads them, so runtime B's config_root/keys/brain-path no
> longer retarget runtime A. Regression tests: `runtime_settings_are_isolated_per_thread`
> + `installed_settings_never_fall_through_to_globals` (`embed_config.rs` 2/2) and
> `multi_instance_embed_config_isolated_across_runtimes` (`sofuu-capi`, 22/22 total).

`crates/sofuu-capi/src/lib.rs:162-174` — every `sofuu_rt_new` calls
`embed_config::configure(...)` / `set_api_key` / `set_brain_path` — process-globals.
Runtime B's `config_root`/keys silently retarget runtime A's brain path, log behavior,
and provider keys, while the ABI header (`lib.rs:18-20`) promises "Multiple runtimes per
process are supported". Data cross-talk for any multi-tenant embedder; single-runtime
hosts unaffected. Not memory-unsafe; P0 only for the embedding contract.

# P1 — active defects (CLI-facing, confirmed at line level)

## A. Agent/chat driver logic

### P1-1. ✅ FIXED 2026-09-02 OpenAI streams never request usage → token budgets, USD budget, and ctx-meter calibration are dead code on spec-compliant OpenAI endpoints

`crates/sofuu-core/src/rt/ai.rs` (request body builder, ~:475-478) — `stream_options`
appears **nowhere in the file** (grep-verified). OpenAI chat-completions omits the final
`usage` chunk unless `stream_options: {"include_usage": true}` is sent. Since every
agent/chat turn is streamed ("Stream-first loop for EVERY provider", agent.js:1639-1643),
`st.usage.promptTokens/completionTokens` stay **0** on stock OpenAI. Consequences:
`budgetBreach()`'s token check (agent.js:997) can never fire → `maxTokens` unenforced;
`costUsd` gated on tokens>0 (chat.js:1172-1178) → `budget_usd` never trips; the ctx
meter falls back to its estimator despite comments claiming provider-anchored
calibration (agent.js:165-166). Anthropic is unaffected (usage rides
message_start/message_delta unconditionally); OpenRouter sends usage unprompted, which
is why live tests on the shared pool pass while stock OpenAI silently reports zeros.
**One-line fix** in the OpenAI body builder (safe to send on all OpenAI-compat
gateways that tolerate extra fields; gate on provider family if cautious).

### P1-2. ✅ FIXED 2026-09-02 Continuation and empty-retry paths drop the abandoned stream's usage

`src/js/agent.js:1267-1302` — on mid-stream cut with text already forwarded,
`streamWithRetry` returns `{ st: st2, parts }` where `st2` is the *continuation* stream;
the caller (agent.js:1716-1731) reads only `st.usage`. The original stream's partial
usage — delivered by ai.rs into the abandoned `st` at `[DONE]`/CURLMSG_DONE — is never
counted. A 95%-delivered answer that cuts and continues is billed as its last 5%.
Same class in the `finish_reason:"length"` retry (agent.js:1767-1778): the retry's
`rr.st.usage` is never read. `tree.promptTokens`, `own.llmCalls`, budget math, and cost
all under-count. Fix: accumulate `st.usage` into `own`/`tree` inside
`streamWithRetry` before abandoning a stream (both paths).

### P1-3. ✅ FIXED 2026-09-02 Shipped `src/js/chat.js` still caps tool loops at 8 steps — the 2026-08-24 fix never landed in the second driver

`src/js/chat.js:1091` — `budget: { maxSteps: 8, ... }` vs the TUI driver's
`maxSteps: (parseInt(env('SOFUU_CHAT_MAX_STEPS'), 10) || 200)` (chat.rs:4244). Every
embedded/headless `sofuu.chat.submit` host runs the 8-step cap: a read→read→grep→edit→
verify coding turn dies at 8 rounds. The salvage path fires (agent.js:1654-1666) so it
is not a bare `(no response)`, but the turn is truncated at 8 where the CLI allows 200,
and `SOFUU_CHAT_MAX_STEPS` has no effect on this driver. Exactly the two-drivers
divergence pattern the repo keeps hitting. **Fix: port the env-tunable 200 into
chat.js:1091.**

### P1-4. ✅ FIXED 2026-09-02 Write jail is lexical only — symlinks defeat it (no realpath anywhere in fs.rs)

`src/js/tools.js:69-77` `mustBeInRoot` = textual `..`-normalization + prefix check;
`crates/sofuu-core/src/rt/fs.rs` opens paths with raw `uv_fs_open` (fs.rs:146, 245, 617)
— **no canonicalize/readlink/O_NOFOLLOW anywhere** (grep-verified). A symlink
`./link → ~/.ssh` inside the project makes `edit_file { path: "link/authorized_keys" }`
pass the jail lexically and write through the link outside the project. Attack needs a
pre-existing in-repo symlink (cloned repo, node_modules, or a prior `bash` call —
`ln -s` is not denied), after which **every** subsequent turn can write outside the
jail, including under permission profiles where write/edit auto-pass with no approval.
Read side: `read_file`/`grep`/`glob`/`list_dir` are deliberately unrestricted
(documented at tools.js:15) — that includes arbitrary-file read of e.g.
`~/.aws/credentials` into model context with no gating (folded into P2-2's
exfiltration chain). **Fix: do the jail check in Rust where `canonicalize` exists (or
add a `sofuu.fs.realpath` and resolve before the prefix check).**

### P1-5. ✅ FIXED 2026-09-02 `mergeStreamToolCalls` fallback `idx = order.length` aliases fragments from non-conforming gateways

`src/js/agent.js:753-782` — when `t.index` is missing, the fragment is keyed by
`order.length` (count of distinct indices so far), which equals a NEW call only if
every fragment either carries an index or starts a new call. Two index-less fragments
in one frame (or a gateway that restarts index at 0 per chunk — vLLM has been observed
doing this) alias: the second fragment's argument string concatenates onto the first
call → `{"city":"Paris"}{"city":"Oslo"}` → `JSON.parse` fails → `{ _raw: … }` passes the
is-object check (agent.js:1795) → the tool mis-executes with garbage args, silently.
Spec-compliant OpenAI/Anthropic always send `index` (the mock test always does), so this
fires only on non-conforming but realistic "OpenAI-compatible" self-hosted endpoints —
a first-class configuration here. **Fix: index-less fragment with a `name` starts a new
call; otherwise append to the last entry.**

### P1-6. ✅ FIXED 2026-09-02 Stopped/errored sub-agent results are reported to the parent as ordinary successful answers

`src/js/agent.js:1604-1630` — `execDelegate` returns
`childRes.answer + '\n[sub-agent …]'` unconditionally. A child that hit its own budget
breach (salvage summary inside) reads to the parent as a normal answer; no `tool error:`
marker (contrast tools.js errors at agent.js:1536), no `stopped` signal the loop reacts
to. The parent cannot distinguish "answered" from "ran out of budget halfway", cannot
retry, and `storeAndFinish` persists the salvage text as memory (it passes the ≥40-char
filter; the tool-error strip at agent.js:1944 doesn't match the suffix). Fix: prefix
stopped children with the `tool error:` marker (or a structured `stopped` field).

### P1-7. ✅ FIXED 2026-09-02 Negative provider usage walks the USD spend cap backwards

`crates/sofuu-core/src/chat.rs:2018-2030` — `pt`/`ct` from `js_to_int` with no `.max(0)`
(two lines below, the cache slots ARE clamped — the intent existed). Negative `pt`
makes `cost` negative; `cfg.spend_total_usd += cost` **decreases** lifetime spend — the
budget preflight (`__chat_budget_check`, enforced at chat.rs:4128-4132) can be walked
back below the cap; the display path wraps `pt as u64` into ~1.8e19 garbage in `/cost`.
Requires a provider reporting negative/overflowing usage — unusual, but the codebase's
own cache-slot clamps show this class was already in the threat model. Fix: clamp both
to ≥0 at parse. (Related P2: `cfg.save()` at chat.rs:2031 rewrites `~/.sofuu/config.json`
— including the API key — every turn.)

## B. Session/persistence layer

### P1-8. ✅ FIXED 2026-09-02 PeerWatch cap-break marks undelivered events as seen — peer broadcasts can vanish

`crates/sofuu-core/src/session.rs:573` (manifest path) and `:600` (flat path) — when
the 8-notice cap (`MAX_NOTICES_PER_POLL`) breaks the inner event loop, `self.seen.insert(id, latest)`
still runs, where `latest` is the high-water mark covering **all** events read including
the ones never iterated into notices. Events 9+ in a burst are marked seen without ever
being delivered and are never re-scanned. A peer's critical broadcast vanishes whenever
>8 critical/note/task events land between two polls. Events survive on disk (no data
loss) but the notification contract is deterministically broken. Fix: advance `seen` to
the last event actually *pushed*, not `latest`/`total`.

### P1-9. ✅ FIXED 2026-09-02 Every session persist failure is silently discarded

`crates/sofuu-core/src/session.rs:402, 458, 465, 472, 480, 488, 496` — all
`let _ = self.persist();` (join, set_task, add_note, broadcast_critical, log_prompt,
log_answer, finish). `persist()` returns `bool` for exactly the failures that matter
(disk full, flock poison, manifest corrupt, seq regression) and every one is dropped.
The chat keeps running with zero indication; the transcript lives only in memory; the
registry heartbeat keeps pointing at a session file that never advanced. Fix: surface a
one-line warning on false at least for log_prompt/log_answer/finish (the `/cost` path
already shows the pattern).

### P1-10. ✅ FIXED 2026-09-02 `/resume <short-id>` is advertised everywhere but never resolved

`crates/sofuu-core/src/chat.rs:3252-3255` lists sessions by short id and says "Use
/resume <id>"; `handleResume` (chat.rs:3272) passes the raw argument to
`__chat_resume_turns` → `session::past_turns` → `load_recent_session_data` with **no
short-id resolution** — unlike `resolve_session_id` (session.rs:814-840) which the
inspect/repair/migrate commands use. Typing the advertised short id yields "Session has
no turns to resume." Only the full 26-char id works. Fix: route through
`resolve_session_id`.

## C. Build / packaging

### P1-11 (lead-auditor finding). `sofuu.SSEParser` (public JS API) corrupts multi-byte UTF-8 split across feeds

`crates/sofuu-core/src/ffi_exports.rs:163-174` — `sofuu_sse_feed` decodes **each chunk
independently** with `String::from_utf8_lossy` before handing it to the Rust parser. A
multi-byte character split across two network reads becomes **two U+FFFD replacement
characters** — silent text corruption. The code comment (":160-161") explicitly names
the hazard ("SSE text may arrive split mid-codepoint across network reads") and chose
lossy anyway. The internal provider path doesn't share the bug — ai.rs's own parser is
byte-level over a `Vec<u8>` (`sse_buf` extends by raw bytes, lines extracted by `\n`
scan, JSON parsed only from complete lines: ai.rs:2231-2260), so provider streams are
safe; only the exported `sofuu.SSEParser` class (http_sse.rs shell, consumed today by
tests/sse_test.js + examples) corrupts. Fix: make `SseParser::feed` take `&[u8]` (or
hold back the incomplete UTF-8 tail between feeds) — the safe pattern already exists
in-repo in ai.rs.

### P1-13. ✅ FIXED 2026-09-02 ABI checker exits 0 on NEW symbols; baseline mixes capi+core symbols

`scripts/check_abi.sh:84-90` — new exported symbols print a warning and `exit 0`
("additive, not breaking"). An accidental new export (typo'd `#[no_mangle]`) passes the

## D. ML subsystem (verified at line level by the lead auditor)

### P1-18. ✅ FIXED 2026-09-02 Supervisor "step"/"budget" semantics differ between runtime and trainer — budget-pressure features are out-of-distribution whenever a turn issues multiple tool calls

`src/js/agent.js:1506-1510` — the runtime passes `step: own.toolCalls` (count of tool
calls made) against `budget: d.budget.maxSteps`, but `maxSteps` bounds LLM **turns**
(`budgetBreach()` fires on `steps >= d.budget.maxSteps` where `steps` counts LLM
turns, each of which can carry several tool calls — agent.js:997). The trainer built
every example with one candidate call per step (`step = calls.len()+1`,
data_supervisor.rs:189-210). The features that consume this — f12 `step/budget`, f13
over-budget flag, f31 `(1-f0)*f12` — saturate early at runtime: with 3 tool calls per
turn and maxSteps=12, f12 hits 1.0 at LLM turn 4 and the over-budget flag at turn 5,
while the real breach is at turn 12. Effect: spurious budget-pressure/over-budget
nudges long before any real breach (advise-only, so cost = noise, but it is the
model's strongest trained channel misfiring). Same skew in the loop checker
(agent.js:1817-1819). Fix: pass budget as a tool-call budget (maxSteps × observed
calls/turn) or pass step as the LLM turn index.

### P1-19. ✅ FIXED 2026-09-02 Compaction `plan()` token sum still plain `u32` — the 2026-08-30 saturating fix landed in features.rs only

`crates/sofuu-core/src/ml/compaction/model.rs:168` — `segments.iter().map(|s|
s.tokens).sum()` wraps on hostile token counts, while features.rs:220 was fixed to
`fold(0u32, saturating_add)` in the hardening pass. The JS shim clamps each segment's
tokens into u32::MAX (so 256×u32::MAX wraps to 4,294,967,040; 255×u32::MAX+300 wraps
to 45 — the computed compaction budget collapses to ~5 tokens and the pass frees the
wrong amount). Release builds wrap silently (overflow-checks off); dev panics inside
the QuickJS callback. One-line fix matching features.rs.

### P1-20. ✅ FIXED 2026-09-02 Alloc `parse_limit`: Output branch steals context-window errors; "context window/size" wordings never match

`crates/sofuu-core/src/ml/alloc/policy.rs:370-399` — the Output branch triggers first

context keyword is present, and extend the trigger list.

### P2-35. ✅ FIXED 2026-09-02 context.rs per-run maps (`sig_first`/`reads`/`writes`) grow without bound; runs created via precheck/track_segment are never evicted

`ml/context.rs:209-217` — only `calls` is capped (MAX_CALLS=256) and per-path reads

### P2-36. ✅ FIXED 2026-09-02 online.rs persist is a non-atomic direct `std::fs::write`

### P2-37 (suspicion). Supervisor skip-set channel (f18/f19) is effectively dead at runtime
